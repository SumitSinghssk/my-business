Running large language models close to users promises lower latency and better data residency, but GPU capacity at the edge is scarce and expensive. We profiled three popular inference runtimes on the same Kubernetes edge clusters to understand where the real trade-offs lie.

The Test Setup

Each runtime served the same 8B-parameter instruction-tuned model on identical nodes with a single 24GB GPU. Load was generated with a realistic mix of short chat turns and long document-summary prompts, from 1 to 64 concurrent users.

  • vLLM with PagedAttention and continuous batching.
  • TensorRT-LLM with an engine compiled for the target GPU.
  • Text Generation Inference (TGI) with default production settings.

TensorRT-LLM was fastest, but it required a model-specific compilation step and a rebuild for every driver or model update. vLLM delivered about 87% of that performance with far simpler operations.

Quantisation Changes the Picture

Moving from FP16 to 4-bit AWQ quantisation roughly doubled the number of concurrent sessions each GPU could hold before memory pressure forced queuing. Quality loss on our evaluation suite was under 2% for summarisation tasks, but noticeably higher for structured data extraction.

“Benchmark on your own prompts. Leaderboard numbers rarely survive contact with real traffic.”

Our Recommendations

  • Default to vLLM for most edge deployments: strong performance and simple operations.
  • Reserve TensorRT-LLM for stable, high-volume models where every millisecond is worth the build complexity.
  • Autoscale on GPU memory utilisation and queue depth, not CPU, or pods will scale far too late.
  • Always keep a regional fallback to a central cluster for when edge capacity is exhausted.
