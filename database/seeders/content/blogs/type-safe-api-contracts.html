Most production incidents between services aren't caused by bugs inside a service. They happen at the boundary: a field renamed in one place and not another, a nullable value that wasn't, a date sent as a string. We eliminated that whole class of failure by making API contracts the single source of truth and generating everything else from them.

Contract First, Code Second

Every service interface is defined before implementation begins, in one of two formats:

  • OpenAPI 3.1 for public and browser-facing HTTP APIs.
  • Protocol Buffers for internal gRPC service-to-service calls.

The contract lives in a shared repository and is reviewed like code. Server stubs, client SDKs and validation schemas are all generated from it in CI.

Runtime Validation at the Edges

Static types disappear at runtime, and data from outside your process is always untrusted. We generate Zod schemas from the OpenAPI spec and validate every inbound request and every response from third parties.

import { z } from 'zod';

export const Invoice = z.object({
  id: z.string().uuid(),
  amountMinor: z.number().int().nonnegative(),
  currency: z.string().length(3),
  issuedAt: z.string().datetime(),
});

export type Invoice = z.infer<typeof Invoice>;

const invoice = Invoice.parse(await response.json());

Breaking Changes Are Caught in CI

A contract diff runs on every pull request. Removing a field, narrowing a type, or making an optional field required fails the build unless the change is explicitly versioned.

“If two services can disagree about a payload, eventually they will, usually at 3am.”

Consumer-Driven Contract Tests

Providers run the recorded expectations of every consumer as part of their test suite. A provider can't deploy a change that would break a consumer, even one they didn't know existed.

Outcome

  • Integration incidents between services fell by 81% over two quarters.
  • New client SDKs are available minutes after a contract merges, not days.
  • Onboarding engineers read the contract repository to understand the whole system.
