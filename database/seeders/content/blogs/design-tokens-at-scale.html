Handoff drift is the quiet tax on every product team. A designer nudges a colour in Figma, an engineer hard-codes the old hex value, and six months later the product ships four slightly different blues. We eliminated that drift by treating design tokens as compiled, versioned source code rather than a shared spreadsheet.

Tokens Are an API, Not a Palette

The mental shift that mattered most: a token is a contract between design and engineering. That means it needs a schema, versioning, and a deprecation policy, exactly like a public API.

We organise tokens into three tiers:

  • Primitive tokens — raw values such as blue-600: #155eef. Never used directly in components.
  • Semantic tokens — intent-based aliases such as color.action.primary that point at primitives.
  • Component tokens — scoped overrides such as button.primary.background for the rare case a component needs to diverge.

One Source, Many Targets

Tokens live as JSON in their own repository. A build step exports them from Figma Variables, validates them against a schema, and compiles them into every platform format we ship:

{
  "color": {
    "action": {
      "primary": { "$type": "color", "$value": "{blue.600}" },
      "primary-hover": { "$type": "color", "$value": "{blue.700}" }
    }
  },
  "radius": {
    "control": { "$type": "dimension", "$value": "4px" }
  }
}

The same source produces CSS custom properties for the web, a typed TypeScript module for application code, and native resource files for iOS and Android.

Type Safety Closes the Loop

Because the TypeScript output is a union of literal token names, referencing a token that doesn't exist is a compile error, not a visual bug found in QA. Renaming a token in Figma breaks the build in every consuming repository until the change is adopted.

“If a design decision can't fail a build, it will eventually fail a customer.”

Visual Regression as the Safety Net

Every token release runs a visual regression suite across our component library. Screenshots are diffed per component and per theme, and any change above a 0.1% pixel threshold requires explicit design sign-off before the package is published.

Results After Twelve Months

  • Hard-coded colour values in application code dropped from 1,140 to zero.
  • Theme changes that used to take a two-week sprint now ship in a single release.
  • Design and engineering review the same artefact, so "that's not what the mockup says" conversations have all but disappeared.
