Warehouses and freight corridors are hostile environments for software. Steel racking blocks Wi-Fi, rural routes drop cellular coverage for hours, and yet a driver still needs to confirm a delivery and a picker still needs to scan a pallet. Our answer is an offline-first architecture where the device, not the server, is the primary source of truth for the user in front of it.

Why "Retry Later" Doesn't Work

The naive approach queues failed requests and replays them when the connection returns. In practice that produces duplicate scans, lost updates when two devices edit the same shipment, and drivers staring at spinners in a loading bay.

We needed three guarantees:

  • Every action completes instantly on the device, with or without a network.
  • Concurrent edits from different devices merge without silent data loss.
  • The final state is identical on every device once they reconnect.

Conflict-Free Replicated Data Types

CRDTs are data structures designed to merge deterministically. Two replicas that have seen the same set of operations always converge to the same state, regardless of the order those operations arrived in.

For shipment state we combine a few simple types:

  • Last-writer-wins registers for fields like the assigned driver, using hybrid logical clocks to order writes.
  • Grow-only sets for scan events, which can never be "un-scanned".
  • Observed-remove sets for exception flags that can be raised and later cleared.
type ShipmentState = {
  driver: LWWRegister<DriverId>;
  scans: GSet<ScanEvent>;
  exceptions: ORSet<ExceptionCode>;
};

// Merging is commutative, associative and idempotent
const merged = mergeShipment(localState, remoteState);

An Event-Sourced Local Ledger

Each device keeps an append-only ledger of operations in local SQLite. The UI reads from a materialised view of that ledger, so it never waits on the network. A background sync worker exchanges operations with the server whenever any connectivity appears, even briefly.

“The network is an optimisation, not a dependency.”

Results in the Field

  • Delivery confirmations complete in under 80ms on-device, down from 2–9 seconds.
  • Duplicate scan incidents fell to zero after rollout across 6,000 vehicles.
  • Operations kept running through a 14-hour regional carrier outage with no manual reconciliation.
